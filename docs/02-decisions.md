## 2026-08-25 · 모델 초상권 **전부 확보** — 영상·모델컷 게재 제약 없음
**발주자 확인.** §8 의 P0 8건 중 7번이 해소됐다.
한국 촬영 계약이 "국내 온라인" 한정인 사례가 흔해 확인 대상으로 걸어 뒀던 항목이다.
**영향**: 브랜드스토리 히어로 영상을 실제 테마에 반영해도 된다.
모델컷을 쓰는 PDP·룩북 설계도 대기 해제.
**주의**: 이 확인은 **초상권**에 한정된다. DISNEY 라이선스 지역(§8-5)은 별개이며 여전히 미확인이다.

## 2026-08-25 · 바이너리 업로드 경로 = **저장소 raw URL 경유**
`fileCreate` 는 `data:` URI 를 거부하고(`INVALID_IMAGE_SOURCE_URL`),
staged upload 은 컨테이너 egress 가 막혀 둘 다 불가였다.
**해법**: 파일을 저장소에 커밋한 뒤 `raw.githubusercontent.com/{owner}/{repo}/{sha}/{path}`
를 `originalSource` 로 넘기면 Shopify 가 서버 측에서 내려받아 자기 CDN 에 복사한다.
같은 원리가 `themeFilesUpsert` 의 body `type: URL` 에도 통해, **텍스트를 손으로 옮겨 적지 않아도 된다**
(이번 세션에서 한글 전사 오류가 20건 발생했던 것을 구조적으로 차단).
**전제**: 저장소가 public 이어야 한다. 비공개 전환 시 이 경로는 깨지며 BASE64 로 대체해야 한다.
**영향**: 로고 업로드·테마 설정 반영 완료. 공개 범위 판단은 발주자 몫으로 `05` §4 에 정리.

## 2026-08-25 · 컬렉션은 **태그 기반 자동 생성**으로 운영한다
**발주자 확인**: 개발 단계 41개, **오픈 시점 300개 이상.**
300개를 사람이 컬렉션에 하나씩 배정하는 운영은 무너진다.
**결정**: 상품 등록 시 태그만 달고, 컬렉션은 태그 조건으로 자동 생성한다.
태그 체계 = 상위(`bra`/`shorts`/`inner`/`leg`) + 하위(`nudebra`/`cami`/`thermal`/`stockings`/`socks`).
`stockings`/`socks` 분리는 **관세 때문**이다 — 스타킹 과세, 양말 면세 가능(`03-jp-tax-duty.md`).
**영향**: 41/41 태그 부여 완료(08-25). 오픈 시 하위 분류·필터를 켤 때 구조를 다시 짤 필요가 없다.
현재 41개는 수동 배정 상태이며 300개 전환 시 자동 컬렉션으로 바꾼다.

## 2026-08-25 · Shopify MCP 커넥터 사고 — **쓰기 전 스토어 확인을 규칙으로**
태그 부여 중 커넥터가 DHALIORA 로 되돌아가 있어 mutation 이 전량 실패했다
(`Product does not exist`). 마른5 상품 ID 라 DHALIORA 에는 **아무것도 쓰이지 않았다.**
**원인**: 커넥터는 계정당 한 스토어이고, Cowork 에서 재인증하면 이쪽 연결이 바뀐다.
**규칙**: 모든 쓰기 작업 전에 `shop { name myshopifyDomain }` 로 대상 스토어를 확인한다.

## 2026-08-25 · 표기 규약 — **대화·문서는 한국어, 적용값은 일본어**
**발주자 요청.** 카테고리·메뉴명을 일본어로만 적으면 발주자가 확인할 수 없다.
`브라(ブラ)` 형식으로 **한국어를 앞에, 실제 투입값을 괄호에** 적는다.
**영향**: `CLAUDE.md` §13 에 규약 추가. 이후 모든 문서·대화에 적용.

## 2026-08-25 · 컬렉션은 **4개로 시작** (초기 상품 소량 전제)
**발주자 확인**: 초기에는 상품을 많이 등록하지 않는다.
Alo Yoga 의 원단 축 구조는 SKU 가 수천 개라 생긴 해법이고, 41 SKU 에 얹으면
컬렉션당 4~5개가 들어가 **재고 부족 신호**로 읽힌다.
**결정**: 브라(ブラ) · 쇼츠(ショーツ) · 이너(インナー) · 레그(レッグ) 4개.
홈웨어(ホームウェア)는 상품 0건이므로 GNB 에서 제외. 원단·필터·신상·베스트셀러는 만들지 않는다.
**기준선**: 컬렉션당 상품 8~10개. 못 채우면 만들지 않는다.
**영향**: `docs/06-ia-collections.md`. GNB 6개로 축소.

## 2026-08-25 · 시간대·중량단위는 **바꿀 필요 없다** (정정)
`CLAUDE.md` §10 의 "되돌리기 어려운 설정" 목록에 시간대(Asia/Tokyo)와 중량단위(g)가 들어 있으나 **근거가 없다.**
- KST 와 JST 는 둘 다 **UTC+9, 서머타임 없음** → 오프셋 동일. 주문 타임스탬프·리포트 일자 경계·예약 발행이 모두 같게 계산된다.
- 관세·배송비에 들어가는 것은 **중량값이지 표시 단위가 아니다.** 40g 을 `0.04 kg` 로 넣어도 결과가 같다.
**영향**: 관리자 조정 대상은 **기본 언어(일본어)** 하나로 줄어든다. 시간대는 애초에 되돌리기 어려운 설정도 아니다.

## 2026-08-25 · JPY 는 **스토어 기본 통화**로만 가능 (마켓 통화 불가)
`marketCreate(currencySettings:{baseCurrency:JPY})` 가 거부됨 —
*"The shop's payment gateway does not support enabling more than one currency."*
**근거**: Shopify Payments 부재 → 다중통화 불가. 한국 법인이라 Shopify Payments(JP) 대상이 아니다.
**영향**: D3 재검토 필요. `04-open-questions.md` 1번 "Shopify Payments(JP) 심사 착수"는 **대상이 없을 가능성이 높다.**
통화 전환은 관리자에서만 되고, 주문이 생기면 잠긴다. **상품 투입 전 필수 선행.**

## 2026-08-25 · 옵션 축 4건 → **2건** (정정)
