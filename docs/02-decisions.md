## 2026-08-25 · 시간대·중량단위는 **바꿀 필요 없다** (정정)
`CLAUDE.md` §10 의 "되돌리기 어려운 설정" 목록에 시간대(Asia/Tokyo)와 중량단위(g)가 들어 있으나 **근거가 없다.**
- KST 와 JST 는 둘 다 **UTC+9, 서머타임 없음** → 오프셋 동일. 주문 타임스탬프·리포트 일자 경계·예약 발행이 모두 같게 계산된다.
- 관세·배송비에 들어가는 것은 **중량값이지 표시 단위가 아니다.** 40g 을 `0.04 kg` 로 넣어도 결과가 같다.
**영향**: 관리자 조정 대상은 **기본 언어(일본어)** 하나로 줄어든다. 시간대는 애초에 되돌리기 어려운 설정도 아니다.

## 2026-08-25 · JPY 는 **스토어 기본 통화**로만 가능 (마켓 통화 불가)
`marketCreate(currencySettings:{baseCurrency:JPY})` 가 거부됨 —
*"The shop's payment gateway does not support enabling more than one currency."*
**근거**: Shopify Payments 부재 → 다중통화 불가. 한국 법인이라 Shopify Payments(JP) 대상이 아니다.
**영향**: D3 재검토 필요. `04-open-questions.md` 1번 "Shopify Payments(JP) 심사 착수"는 **대상이 없을 가능성이 높다.**
통화 전환은 관리자에서만 되고, 주문이 생기면 잠긴다. **상품 투입 전 필수 선행.**

## 2026-08-25 · 옵션 축 4건 → **2건** (정정)
파서가 값 내부 하이픈을 구분자로 오인하고 있었다. `858` 의 `S-M` 은 사이즈 범위였다.
**근거**: `data/details.json` 원본 재파싱. 진짜 4축은 `103`·`139` (수량×유발무발×컬러×사이즈).
**영향**: P0-1 상품 분리 대상이 3건 → 2건으로 축소. `scripts/options.py` 로 파서 교체.

## 2026-08-25 · 옵션 축은 **위치가 아니라 역할**로 매핑한다
a1=수량 / a2=컬러 / a3=사이즈 가정이 40건 중 **4건**에서 깨진다 (`714`·`103`·`139`·`14`).
**영향**: 이관 스크립트는 값 패턴으로 축 역할을 판정한다. 사이즈 표기 흔들림 2쌍도 정규화.

## 2026-08-25 · 상품은 전량 **DRAFT** 로 투입한다
**근거**: 일본어 상품명이 없다. 무감수 자동번역은 §13 금지. JPY 정가표도 미확정.
**영향**: 네이티브 카피 + JPY 정가표 확정 전까지 공개하지 않는다.

## 2026-08-24 · 무료배송 임계 ¥9,800 → **¥8,800** (정정)
**근거**: Catalog MCP 실측 가격대가 ¥676~¥3,769. ¥9,800 은 4~5점을 담아야 하는데 일본 이너웨어 D2C 통상 장바구니는 2~3점.
브라 3점 = ¥8,431 에서 한 점만 더 담으면 ¥10,241 → 0.6掛け 폐지 후 면세 한도 초과, 전 품목 과세.
**영향**: 홈 디자인안의 프로그레스바 목표값, 배송 정책 페이지, 관세 고지 문구.
**부수 요건**: 장바구니가 ¥10,000 에 접근하면 경고하는 장치 필요.

## 2026-08-24 · 옵션 축 "2축" → **최대 4축** (정정)
